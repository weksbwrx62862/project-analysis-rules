# 分析检查清单

> 这是一份可打印的完整检查清单。按 6 阶段递进执行，勾选已完成项。

---

## 阶段 0：前置准备

- [ ] 执行 `gitnexus analyze -f` 索引目标项目
- [ ] 确认项目语言，查看语言兼容性表（[gitnexus-integration.md](../gitnexus/gitnexus-integration.md)）
- [ ] 记录图谱统计（节点数、边数、集群数、流程数）
- [ ] 阅读项目 README / 文档，一句话总结核心价值

---

## 阶段 1：视角定位（~5% 时间）

- [ ] 确定分析聚焦点（勾选 1-2 项）：
  - [ ] 宏观架构 — 学习模块划分和分层设计
  - [ ] 中观模块 — 学习某个子系统的实现
  - [ ] 微观实现 — 学习具体算法或数据结构
  - [ ] 设计模式 — 学习设计模式的实际运用
  - [ ] 工程实践 — 学习测试/CI/构建等工程化手段
  - [ ] 特定技术 — 学习某种技术的最佳实践
- [ ] 设定时间预算：□ 快速(15min) □ 标准(45min) □ 深度(90min+)
- [ ] 如项目有 ADR（Architecture Decision Records），已阅读
- [ ] 产出：分析聚焦声明 + 时间预算

---

## 阶段 2：结构扫描（~15% 时间）

### 目录树直觉判断
- [ ] 识别项目结构：□ 单体 □ Monorepo
- [ ] 识别组织方式：□ 按功能 □ 按层次 □ 混合
- [ ] 识别核心模块位置

### 入口点识别
- [ ] CLI 入口
- [ ] HTTP 入口（路由、中间件链）
- [ ] 事件入口
- [ ] 定时任务入口

### 模块边界
- [ ] 每个核心模块一句话职责描述
- [ ] 依赖方向箭头图（ASCII）
- [ ] 存在上帝模块？（单文件 > 2000 行）
- [ ] 领域层是否依赖基础设施层？
- [ ] 第三方库渗透深度？

### GitNexus 辅助
- [ ] `impact` 核心模块 → 波及范围
- [ ] `cypher` 循环依赖检测
- [ ] `cypher` 被依赖排行 Top 10
- [ ] `cypher` 无被依赖模块（死代码候选）

### 产出
- [ ] ASCII 模块依赖图
- [ ] 模块职责清单
- [ ] 架构关键节点识别

---

## 阶段 3：流程追踪（~25% 时间）

### 挑选关键流程
- [ ] 流程 1（如 HTTP 请求 → 响应）
- [ ] 流程 2（如 启动 → 配置 → 运行）
- [ ] 流程 3（根据项目特点选择）

### 逐层记录
- [ ] 每层做了什么？为什么在这一层？
- [ ] 数据在层间如何转换？
- [ ] 错误如何传播？
- [ ] 哪里有缓存？什么策略？
- [ ] 同步/异步边界在哪里？
- [ ] 资源获取/释放点
- [ ] 并发点（锁、channel、promise）

### GitNexus 辅助
- [ ] `query` 搜索关键流程
- [ ] `context` 查看入口函数的完整调用链
- [ ] `cypher` 多跳调用链追踪
- [ ] `cypher` 中间件/拦截器识别

### 产出
- [ ] 2-3 条核心流程的时序图
- [ ] 每个环节的设计解读
