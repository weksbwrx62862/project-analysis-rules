## 阶段 1：项目定位

> 一句话：Express 是 Node.js 的极简 Web 框架，通过中间件链串联请求处理，奠定了 Node.js 服务端开发的范式。

### 架构风格识别

**管道/过滤器模式 + 极简核心**。Express 的核心非常小（~2,000 行），几乎所有功能通过中间件扩展。

## 阶段 2：结构扫描

### 模块职责清单

| 模块 | 职责 | 备注 |
|------|------|------|
| `lib/router/` | 路由匹配和分发 | 核心之一 |
| `lib/application.js` | App 工厂、配置、listen | 用户入口 |
| `lib/request.js` | Request 对象增强 | 原型链扩展 |
| `lib/response.js` | Response 对象增强 | 原型链扩展 |
| `lib/middleware/` | 内置中间件（query、init） | |
| `lib/view.js` | 模板引擎支持 | 可选功能 |

### 架构关键节点

| 模块 | 依赖数 | 风险 |
|------|--------|------|
| `lib/router/` | 高 | 🔴 核心，所有请求必经之路 |
| `lib/application.js` | 中 | 🟡 用户入口 |

### 架构发现

- ✅ 核心极度精简（~6,000 行）
- ✅ 职责清晰：Router 只做路由匹配，中间件做具体处理
- ⚠️ 使用原型链扩展 `req`/`res` — 这种模式在现代 JS 中已经不推荐了

## 阶段 3：流程追踪

### 流程 1：HTTP 请求 → 响应

```
Client → Node.js HTTP Server
  → app.handle() (Application)
  → router.handle() (Router)
  → 遍历 middleware stack
    → middleware(req, res, next) ... next()
    → middleware(req, res, next) ... next()
    → ... 直到某个 middleware 发送响应或达到栈底
  → Response → Client
```

**关键设计决策**：
1. **next() 是核心协议**：中间件调用 `next()` 传递控制权，不调用则终止 — 这就是整个框架的契约
2. **中间件栈是线性的**：不同于 Koa 的洋葱模型，Express 是线性执行（虽然后来加了洋葱式错误处理）
3. **Router 可以嵌套**：`app.use('/api', apiRouter)` — 路由器也是中间件

### 流程 2：错误处理流程

```
错误抛出 → Express 跳过普通中间件 → 找到第一个 (err, req, res, next) 签名的错误处理中间件
  → 执行错误处理 → 发送错误响应 / 传递给下一个错误处理
```

### 值得注意的设计

1. **req/res 的原型链扩展**：`app.request` / `app.response` 可以在不修改核心的情况下给 req/res 添加方法
2. **Router 即中间件**：`router` 本身实现 `(req, res, next)` 接口，可嵌套

## 阶段 4：模式识别

### 设计模式

| 模式 | 位置 | 评价 |
|------|------|------|
| **责任链** | middleware stack | ✅ Express 的招牌模式 |
| **工厂模式** | `express()` 创建 app | ✅ 简洁直观 |
| **适配器** | `req`/`res` 增强 | ⚠️ 原型链扩展 — 有性能成本 |
| **代理** | `req` 方法转发 | ✅ 灵活的封装方式 |

### 与 Koa 的对比

| 维度 | Express | Koa |
|------|---------|-----|
| 中间件模型 | 线性 `next()` | 洋葱模型 `await next()` |
| async 支持 | 较晚加入，体验一般 | 原生 async/await |
| 大小 | 极简核心 (~6k 行) | 更极简 (~2k 行) |
| 生态 | 巨量中间件 | 中间件较少 |
| 设计哲学 | 实用主义 | 追求更现代的 JS |

### 独特解法

1. **极简哲学**：核心只做路由和中间件链 — 模板引擎、静态文件、body 解析都是可选的
2. **原型链扩展的灵活性**：虽然不现代，但给了生态环境极大的自定义空间

## 阶段 6：精华提炼

### 可复用模式

#### 模式 1：责任链作为可扩展架构
- **描述**：通过 `next()` 将请求传递给下一个处理器，中间件可以决定处理还是传递
- **适用**：任何需要可扩展处理链的项目
- **演示**：
  ```javascript
  app.use(logger);        // 先日志
  app.use(auth);          // 再认证
  app.use(router);        // 最后路由
  app.use(errorHandler);  // 错误处理
  ```

#### 模式 2：Router 作为可组合单元
- **描述**：每个 Router 是一个独立的中间件，可以挂载到不同的路径前缀上
- **适用**：模块化 API 设计

#### 模式 3：极小核心 + 丰富生态
- **描述**：核心只解决最本质的问题，其他一切留给生态
- **适用**：构建长期演进的框架或平台

### 陷阱警告

1. **忘记调用 `next()`**：最常见的 Express bug — 请求永远挂起
2. **错误处理中间件的签名**：必须 4 个参数 `(err, req, res, next)`，少一个就不会被识别
3. **同步异常不会自动捕获**：Express 4 不会捕获 `async` handler 中的异常（Express 5 修复）

### 学习行动计划

1. **第一步**：从零实现一个简易的 Express-like 框架（~200 行），理解中间件链的机制
2. **第二步**：对比 Express 和 Koa，理解不同中间件模型的设计哲学
3. **第三步**：研究 `connect`（Express 的前身），看一个中间件框架如何演进
